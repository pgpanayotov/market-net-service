# P5: HTTP API — phase log (2026-10-18)

## What was built

**`src/MarketData.Api`**
- `Program.cs`: MVC controllers with `AddXmlDataContractSerializerFormatters`, `RespectBrowserAcceptHeader`,
  `ReturnHttpNotAcceptable`; `AddProblemDetails` with `XmlProblemDetailsWriter` registered first;
  `UseExceptionHandler` + `UseStatusCodePages`, so errors raised outside MVC also become ProblemDetails;
  API-key auth plus the `Admin` policy; health checks; OpenAPI (`/openapi/v1.json`); OpenTelemetry metrics and traces
  (ASP.NET Core, HttpClient, meter `MarketData`). The OTLP exporter is turned on when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.
  `public partial class Program` is there for `WebApplicationFactory`.
- `Errors/XmlProblemDetailsWriter`: an `IProblemDetailsWriter` that serializes MVC's `ProblemDetailsWrapper` /
  `ValidationProblemDetailsWrapper` with `DataContractSerializer` as `application/problem+xml`. That is the same XML
  MVC produces, so 401s, unmatched routes and exception-handler output match MVC errors. It writes only when an
  XML type wins the `Accept` header (ranked by q, then by position; `*/*` and JSON mean JSON).
- `Errors/NotAcceptableFilter`: a global resource filter that returns 406 **before the action runs** when `Accept`
  names no JSON or XML type (see the deviations below).
- `Auth/ApiKeyAuthenticationHandler`: `X-Api-Key` compared in constant time with `Admin:ApiKey`. If no key is
  configured, every admin request is rejected. The challenge sends `WWW-Authenticate: ApiKey header="X-Api-Key"`.
- `Binding/UtcDateTimeOffsetModelBinder`: binds `s` as ISO-8601 and reads it as UTC when it has no offset. It also
  accepts an unencoded `+` offset, which reaches the server as a space.
- `Controllers/PricesController`: `GET /api/{symbol}/24hAvgPrice` and
  `GET /api/{symbol}/SimpleMovingAverage?n&p&s&series&count&includePoints`. `AnalysisResultExtensions` maps
  `Invalid` → 400 ValidationProblem (keys `symbol`/`n`/`p`/`s`/`count`), `UnknownSymbol` → 404 with
  `detail: "Unknown symbol"`, and `NoData` → 404 with `detail: "No data available"`.
- `Controllers/SymbolsController` (`[Authorize(Policy = "Admin")]`):
  - `GET /api/admin/symbols` returns a `SymbolList` with `lastCandleAt`.
  - `POST` checks the name (400), then Binance exchangeInfo (400 if not a TRADING spot symbol, 503 if Binance can't
    be reached). It then writes and notifies in one transaction: 201 + `Location` when created, 200 when reactivated,
    409 when already active.
  - `DELETE /{symbol}` returns 204 when deactivated or already inactive, and 404 when unknown.
- `Symbols/SymbolAdminService`: runs `ActivateAsync` / `DeactivateAsync` and, only when something changed,
  `IPgNotificationPublisher.NotifyAsync(symbol_changes, SymbolChangedPayload)` inside one EF transaction.
- `Caching/CachingPriceAnalysisService` (+ `AnalysisReadSnapshot`, `AnalysisCache`, `AnalysisCacheOptions`): the
  `IPriceAnalysisService` decorator (see the caching notes below).
- `Health/DatabaseHealthCheck`: `/health/live` runs no checks. `/health/ready` runs `database` (`CanConnectAsync`)
  and `migrations` (`PendingMigrationsHealthCheck`).
- `ApiMetrics`: `marketdata.analysis_cache.lookups{endpoint,result=hit|miss}` on the shared `MarketData` meter. It is
  a separate `Meter` instance with the same name, so `MarketDataMetrics.cs` (which P4 may edit) was not touched.
- `appsettings*.json`: `Admin:ApiKey` (empty in base settings, `dev-admin-key` in Development),
  `MarketData:Binance:RestBaseUrl`, `MarketData:Cache:*`, and a local connection string in Development.

**`src/MarketData.Infrastructure/Binance/ExchangeInfoSymbolValidator.cs`** (new file, the only Infrastructure change)
- `IExchangeSymbolValidator.IsTradableAsync(SymbolName)`, `ExchangeInfoUnavailableException`, `ExchangeInfoOptions`
  (`MarketData:Binance:RestBaseUrl`, `CacheDuration` = 1h), and DI `AddExchangeInfoSymbolValidator(options)`, which
  calls `AddBinance` with a custom environment when a base URL is set.
- It loads **all** TRADING spot symbols with one call,
  `SpotApi.ExchangeData.GetExchangeInfoAsync(PermissionType.Spot, showPermissionSets: false, SymbolStatus.Trading)`, and
  keeps the set for 1h. The double-checked refresh runs behind a `SemaphoreSlim`. A failed call is not cached, so the
  next POST retries.

**`tests/MarketData.Api.IntegrationTests`** (65 tests)
- `ApiFixture` (assembly fixture): one `postgres:17-alpine` Testcontainer, `MigrateAsync` (test-only), and one
  `ApiFactory : WebApplicationFactory<Program>` (environment `Testing`, connection string and admin key through
  `UseSetting`, `StubExchangeValidator` in place of Binance). Before each test it truncates candles, deletes added
  symbols, reactivates the seed symbols and clears the analysis cache. Parallelization is off (`xunit.runner.json`).
- `ContentNegotiationTests`: every GET endpoint (avg, SMA, SMA series, admin list) as JSON, as XML, and 406 for
  `text/csv`. POST and DELETE as JSON/XML/406. A 406 POST writes nothing. An XML request body is accepted. Bodies
  deserialize into the shared Contracts with both serializers. `Accept` q-values are honoured. The OpenAPI document
  lists the routes and `application/xml`.
- `ErrorResponseTests`: 400 as XML ValidationProblem, keyed `n`, `p`, `s` (future and unparseable), `count` and
  `symbol`; 400 as JSON; 404 unknown symbol / no data / unmatched route as XML; 401 as XML (no key) and as JSON
  (wrong key, with the `WWW-Authenticate` header); unmatched route with no `Accept` → `application/problem+json`.
- `AdminSymbolsTests`: the list with `lastCandleAt`. A test `LISTEN symbol_changes` connection checks that:
  - create → 201 + `add` notification;
  - already active → 409 and no notification;
  - not tradable → 400, no write, no notification;
  - exchangeInfo outage → 503;
  - remove → `remove` notification; a repeated remove → 204 and no notification; re-add → 200 + `add` with the same id;
  - an unknown remove → 404;
  - a removed symbol stays queryable.
  - **Rollback:** a publisher that sends `pg_notify` and then throws before commit gives a 500 (as XML
    ProblemDetails from the exception handler), no stored symbol and **no notification**.
  - "No notification" is checked with a sentinel `pg_notify` sent afterwards, which has to be the next payload
    (notifications arrive in commit order), so the test never sleeps.
- `AnalysisCachingTests`:
  - a newly stored candle changes the 24h average and the SMA on the very next request;
  - a repair *behind* the newest candle is served from cache until a newer candle arrives (this proves caching works);
  - `s` values in one bucket share a result;
  - `s` with no offset is UTC, the same as `%2B02:00` and an unencoded `+02:00`;
  - a settled window (more than 48h old) survives new candles;
  - the last series element equals the single value;
  - `includePoints=false` omits the points.
- `CachingPriceAnalysisServiceTests` (NSubstitute, no DB): a miss runs exactly one symbol lookup and one
  newest-candle probe; a hit runs only the probes; errors are not cached; invalid requests don't touch the DB.
- `HealthTests`: live and ready are healthy on the migrated DB. Against an empty database (pending migrations),
  live is 200 and ready is **503 Unhealthy**.

## Decisions and deviations

- **Avoiding the redundant probe (task item 4).** The decorator needs `latestOpenTime` for the key, and
  `PriceAnalysisService` reads it again (plus the symbol lookup). Core is out of scope for this phase, so instead of
  changing the service, the decorator builds its own inner `PriceAnalysisService` over a per-request
  `AnalysisReadSnapshot`. That is a read-only `ISymbolRepository` + `ICandleQueryRepository` view that memoizes
  `FindAsync` and `GetLatestOpenTimeAsync`. A cache miss therefore costs symbol lookup + probe + one analysis query,
  and a hit costs symbol lookup + probe. A side benefit: the stored result is computed from exactly the
  `latestOpenTime` in its key, even if a candle lands mid-request. The snapshot's write methods throw
  `NotSupportedException`; admin endpoints use the real repository.
- **SMA cache key uses `referenceTime`, not the raw `s`.** The result depends on `s` only through
  `referenceTime = floor(min(s, dataEnd), p)`, so the decorator repeats that one line of ADR-006 anchoring and keys on
  `(symbol, n, period, referenceTime, seriesCount, includePoints, latestOpenTime)`. All `s` values in one bucket share
  an entry. A test pins this.
- **Settled windows drop `latestOpenTime` from the key.** ADR-006 says to cache results whose window ends more than
  48h before `latest` for 1h sliding. With `latestOpenTime` in the key such an entry would be orphaned after a minute,
  which defeats the 1h rule. So for settled windows (`referenceTime ≤ dataEnd − 48h`) the key leaves the version out.
  The 24h average always ends at `latest`, so it is never settled. *Edge case:* if the worker was down for more than
  48h, tail backfill later writes data older than the gap-scan window, and a settled entry can stay stale until it
  goes 1h without a hit. This is accepted and could be bounded with an absolute cap if needed.
- **A dedicated, size-limited `MemoryCache`** (`AnalysisCache`, `SizeLimit` 200k units; one entry costs 1 + points +
  series items) instead of the shared `IMemoryCache`. With `SizeLimit` set, every entry must declare a size, which
  would break other users of a shared cache.
- **406 before the action runs (`NotAcceptableFilter`).** `ReturnHttpNotAcceptable` alone decides 406 only while
  formatting the result. That is *after* `POST /api/admin/symbols` has committed and notified, and it never applies
  to 204 results. The filter rejects unsupported `Accept` headers up front, so a 406 means nothing happened and DELETE
  negotiates too. 401 still comes first, because authorization runs in middleware.
- **404 ProblemDetails:** `detail` is exactly `"Unknown symbol"` / `"No data available"` (system-design §5.3), and
  the title is the standard "Not Found".
- **Binance unavailable on POST → 503** ProblemDetails. This status isn't in the spec table, but treating an outage
  as "not tradable" (400) would be wrong.
- **POST response body** is the stored `SymbolDto` (re-read after commit with `ListAsync`, so `createdAt`/`lastCandleAt`
  are real). `Location` is `/api/admin/symbols/{name}`.
- **exchangeInfo is cached as the full TRADING set** (one call per hour), not per symbol. One request answers every
  add, and Binance's "invalid symbol" error code never has to be told apart from a real failure.
- **Config key `MarketData:Binance:RestBaseUrl`** was chosen here. If P4 uses a different key for its REST/WS base
  URLs, align them at merge (the shared notes folder has a hand-over note).
- `GenerateDocumentationFile` is on in the Api project (XML comments feed the OpenAPI document), with `CS1591`
  suppressed so undocumented public members don't fail the build.
- No new packages. `Directory.Packages.props` and the lock files are unchanged.
